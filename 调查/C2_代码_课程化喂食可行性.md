## 一、结论先行

**部分可行，MVP 成本为"小"（零额外前向计算）。**

课程调度器可以落地，但**不应该**、也**没必要**用"每条样本喂前都跑一次模型打分"的方式实现。
现有代码里已经有一个免费的、逐样本的模型能力信号——`d.learn()` 在每次喂食时都会对样本计算
`mean_nll` 惊讶度（`dolphin/model.py:119-137`），并存进缓冲的 `Experience.surprise`。
课程调度器只需：

1. 让解析器把**元数据难度标签**（CMATH 的 `grade`、GSM8K 的步骤数、SynLogic 的 easy/hard 等）随记录带出来（当前被丢弃）；
2. 在 `feed_from` 的取记录处加一个**可选**的调度层：按"模型能力 EMA 相对带通中心的位置"选择下一批记录的难度档；
3. 用 `learn()` 已经算好的惊讶度更新能力 EMA——**零额外 GPU 开销**。

**MVP 定义（最小可行版本）**：
- 新文件 `dolphin/curriculum.py`（或先放在 `feed.py` 内），实现一个 `Curriculum` 对象：
  - 状态：`ability_ema`（惊讶度指数移动平均）、`per_source_per_tier_cursor`、`enabled`。
  - 策略：`ability_ema` 低于带通下界（模型觉得太简单）→ 上调难度档；高于上界（太难）→ 下调；在带内 → 维持当前档。
- `datasets.py` 的 4 个解析器各加一行 `yield {... , "difficulty": ...}`（CMATH=grade、GSM8K=步骤数、SynLogic=0/1、LogiConBench=语句数）；`serialize()` 忽略该键，输出文本不变。
- `feed_from` 增加 `curriculum=None` 参数；默认 `None` 时行为与现在逐字节一致（现有测试全绿）。
- 存档：在 v3 payload 增加可选键 `"curriculum"`，`load()` 用 `.get()` 恢复（缺省 `None`，旧档兼容）。

**结论：MVP 不需要 GPU 预打分、不需要改体验选择逻辑、不破坏断点续喂/反刍状态机，约 200 行内可完成。**

## 四、难度打分候选实现与成本估计

### 候选 A：元数据难度标签（MVP，零额外计算）✅ 推荐
- 直接用 `grade` / 步骤数 / easy-hard / 语句数作为难度档位。
- 模型能力 = `learn()` 已经算好的 `surprise` 的 EMA（免费）。
- 策略：能力 EMA 相对 `buffer.band()` 中心±宽度 的位置决定下一批取哪一档。
- 成本：`0` 额外前向；只改解析器 + 一个调度对象。

### 候选 B：mean_nll 惊讶度预打分（模型在环，有额外成本）
- 喂前对候选样本跑 `awake().model.mean_nll(data, device)`，选惊讶度落在带通内的样本。
- 成本估算（依据：GTX 1060 3GB / 57M 模型 / block_size=256）：
  - 57M FP32 权重 ≈ 228MB；双半球 456MB + 睡脑 AdamW 优化器状态 456MB ≈ **~1.0GB 常驻**，3GB 显存放得下。
  - 单次前向 (1, 256) ≈ `2×57M×256 ≈ 29 GFLOP`；1060 FP32 实际 ~3 TFLOPS → **约 10ms/块**，加 Python 开销实估 **15-30ms/块**。
  - `mean_nll` 最多 8 块（`model.py:127-136`）：长样本最坏 **~120-240ms**；典型序列化样本（问+答，100-1500 字节）1-6 块 → **15-180ms**。
  - 现有喂食已经为每条样本付这个钱（`dolphin.py:205`），所以**能力 EMA 是免费的**；只有"喂前给 K 个候选打分"才是新增成本。
  - 若每 B 条喂食决策一次、每次打 K 个候选：开销放大系数 ≈ `1 + K/B`。K=8、B=64 → **1.125 倍**；K=8、B=8 → **2 倍**。批量决策可把开销压到很低，但 MVP 不需要。

### 候选 C：长度/步骤启发式（零计算，但精度低）
- 用 prompt 长度、答案长度、`reasoning_step` 当难度代理。GSM8K 步骤数（英文 answer 的 `<<>>` 计数）实测分布良好。
- 成本：`0`；可作为候选 A 的补充特征（如 CMATH 同年级内按 `reasoning_step` 再细分）。

**建议**：MVP = A（元数据档位）+ 免费的能力 EMA；把 B 作为后续"课程校准"实验选项（每 N 条用少量候选样本校准档位映射，不做全量预打分）。

## 七、风险清单

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 律 L4 带通被"课程化"绕过 | 若调度器只喂单档，缓冲惊讶度分布变窄 → `band()` 中心/宽度塌缩（`experience.py:56-72`）→ 选择失衡 | 调度器只决定"喂什么候选"，**选拔仍走带通**；保持档位间自然方差；带通统计窗口足够宽 |
| 律 L7 窗口去重 | 低档位样本少（CMATH 每 grade 仅 100 条 dev），跨周期重复喂入受 L7 窗口惩罚但允许 | 课程游标支持循环；不修改 `select` 的重复惩罚 |
| 律 L8 评测 split 禁入训练粮 | 调度器若跨源取数可能误取 test/dev（如 cmath_test、GSM8K test split） | 解析器层已只读 train split；课程调度**只作用于解析器产出的记录**，不新开文件读取 |
| 律 L3 醒脑冻结 | 课程预打分若用睡脑算惊讶度会读到训练中的权重 | `mean_nll` 走 `awake()`（`dolphin.py:205`），调度器沿用 |
| 律 L11 人工接口 | 难度阈值若写死成绝对分档违反"值自成" | 档位切换只参考模型相对信号（带通中心±宽度、能力 EMA），不设绝对惊讶度门槛 |
| 现有测试变红 | `t_g3_feed_cursor` 的游标精确相等、`t_g3_structural_reward` 的 reward 序列 | 默认 `curriculum=None` 路径零改动；新增测试全部走沙箱冷层 |
| 显存/性能 | 候选 B（预打分）在 1060 3GB 上若每批打分太多会与睡脑训练抢 GPU | MVP 用候选 A（零额外前向）；预打分仅在实验开关下、批量低频进行 |
| 数据质量 | school_math/MetaMath 为 AI 生成，难度标签可能失真；CMATH grade 为人工标注最可靠 | 课程化先从 CMATH/SynLogic/GSM8K 三源开始，MetaMath/distil 暂不参与难度分档 |
| 存档兼容 | 新增 `"curriculum"` 键若处理不当破坏旧档 | 用 `.get()` 缺省 `None`；旧档加载后课程关闭，行为不变（仿 feed_cursor 先例） |
