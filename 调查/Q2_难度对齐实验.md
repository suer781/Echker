# Q2 难度对齐实验：CMATH grade 元数据档位 vs 模型 mean_nll 惊讶度

> 实验 Agent：Q2（全新会话，只读沙箱）｜日期：2026-10-05
> 目的：为课程调度器 MVP（Band-Tier Matching，按难度档位喂食）提供前置证据——
> 验证 CMATH 的 `grade`（年级）标签是否与模型对该样本的惊讶度（`mean_nll`）单调对齐。
> 全程只读：未训练、未保存模型、未触碰任何生产资产（`probes/probe.txt`、`dolphin/memory_cold.jsonl`、`dolphin/*.pt` 均未修改）。

---

## 一、结论先行

**在当前可用种子模型上，CMATH `grade` 与模型 `mean_nll` 不显著相关 → 按实验预设的裁决规则，判为「不支持直接用元数据难度档位做课程轴」。**

- 全量 600 条：逐样本 Spearman **ρ = 0.032（p = 0.438）**；Kruskal-Wallis 六组 **p = 0.413**——完全不显著。
- 主抽样 300 条（每组 50）：ρ = 0.086（p = 0.137），KW p = 0.639——同样不显著。
- 每组均值的差异极小（六组均值跨度仅 **0.0037 nats**，约为总体 std 的 0.22 倍），模型对所有样本的 NLL 都落在 5.49±0.02（≈ ln 256 = 5.545 的均匀先验附近）。

**关键 caveat（决定如何解读）**：本实验使用的指定归档 `实验记录/发育实验归档_20261004/state.pt` 经查是**实验前归档的近随机模型**（awake 半球 probe loss = 5.4985，仅比均匀先验 ln 256 低 0.047；可训练参数 128,768，cfg=d64×2L×block192），并非任务描述中「probe 已降到 3.395」的已训练模型。近随机模型的惊讶度对所有文本几乎恒等（字节频率先验主导），**既没有 grade 梯度，也没有任何「纯模型惊讶度」梯度可用**。

因此建议（详见 §七）：

1. **不采用**「CMATH grade 直接作为 Band-Tier Matching 难度轴」的冷启动假设；
2. **也不建议**冷启动时切换到「纯模型惊讶度驱动」——近随机模型下惊讶度本身是平的，纯惊讶度课程同样无梯度；
3. **建议 MVP 改为**：冷启动期线性喂食（不启用档位切换）→ 等模型 probe 明显下降（有可区分结构）后，用**惊讶度分位数分桶**（数据驱动难度轴）或 grade 分桶+周期性校准；
4. **必须补做一次验证**：在已训练模型（probe ≤ 4）上重跑本实验（脚本已就绪，10-30 秒）。若届时 ρ 显著，再启用 grade 轴（解析器加键的改造不变，零额外成本）。

### 混杂检查（n=300）

| 检验 | 统计量 | p 值 | 含义 |
| --- | --- | --- | --- |
| Spearman（grade vs 文本长度） | ρ = 0.4915 | 1.18e-19 | 高年级题目确实更长（grade 携带一定复杂度信号） |
| Spearman（文本长度 vs nll） | ρ = 0.0679 | 0.2413 | 但长度不预测模型惊讶度 |

## 六、讨论与局限

1. **模型近乎随机是本结果的直接原因**。awake 半球 probe=5.4985，仅比 ln 256 低 0.047；对所有 CMATH 样本的 NLL 都压在 5.49±0.02。此时模型只学到极弱的字节频率先验（中文 UTF-8 三字节模式、数字/空格频次），`mean_nll` 几乎不随语义变化。这不是 grade 标签的「错」，而是**冷启动模型没有可被惊讶的结构**。
2. **纯惊讶度驱动在冷启动下同样无梯度**。若改用「模型惊讶度分位数分桶」做难度轴，在近随机模型上分桶结果等价于随机分桶（所有样本惊讶度几乎相同）。因此本实验不能支持「切换到纯惊讶度课程」作为冷启动方案——两种方案在冷启动时都平坦。
3. **结论的外推边界**。本结论仅对「近随机/冷启动模型」成立。已训练模型（如发育实验 222 周期后 probe≈3.4 的模型）可能对 grade 1 与 grade 6 的题目表现出显著不同的惊讶度——这需要重跑验证，不能从本实验否定。
4. **数据量充足**。全量 600 条（每 grade 100）分层抽样，统计功效足够；组间差异若存在且达到可观测量级（≥0.2σ），KW 应有显著信号。实测组间跨度仅 0.22σ，即便补更多样本也难翻盘。
5. **任务描述与归档实物的差异已透明披露**（见 §二）。若后续拿到 probe≤4 的已训练存档，用同一脚本重跑即可（约 10-30 秒）。

## 七、结论与对课程 MVP 的建议

### 裁决

按实验预设规则（grade 与 NLL 显著相关 → 支持元数据难度档位；不相关 → 改用纯惊讶度驱动）：

> **本实验判为「不相关」→ 不支持把 CMATH grade 直接作为课程难度轴。**

### 对 Band-Tier Matching MVP 的具体建议

1. **冷启动期（probe 尚未显著下降，如 >5.0）**：不启用档位调度，按现有线性喂食。此阶段无论元数据档位还是模型惊讶度都没有可用梯度，课程调度是空转。
2. **模型具备可区分结构后（probe 明显下降，如 <4.5）**：优先采用**惊讶度分位数分桶**作为难度轴（数据驱动，不依赖元数据标签），或保留 grade 分桶但**周期性校准**（每 N 批用少量候选样本的惊讶度重标定档位映射——即 C2 报告候选 B 的低频校准版）。
3. **不要删除解析器加 `difficulty` 键的改造**（成本为零，`serialize()` 自动忽略多余键）：grade 仍可用于「候选池浏览顺序」和「人工可解释的报告字段」，只是不作为调度决策的硬轴。
4. **补做验证实验**（前置门槛）：在已训练模型上重跑 `调查/Q2_难度对齐实验.py`。若 ρ≥0.3 且 KW p<0.05，则 grade 轴可信，恢复 Band-Tier Matching 原设计；否则彻底弃用元数据难度轴。

## 八、复现方式

实验脚本：`调查/Q2_难度对齐实验.py`（已留在工作区）。

```bash
# 主实验（每组 50，n=300，CUDA 可用则自动用 GPU）
python 调查/Q2_难度对齐实验.py --seed 20261005 --per-grade 50

# 稳健性（全量每组 100，n=600）
python 调查/Q2_难度对齐实验.py --seed 20261005 --per-grade 100
```

脚本要点：
- 只读加载 `实验记录/发育实验归档_20261004/state.pt`：`torch.load(..., weights_only=True)` → `Config(**ck["cfg"])` → `ByteTransformer(cfg).load_state_dict(ck["states"][ck["awake_idx"]])`，不实例化生产 Dolphin、不写任何模型文件。
- 数据：`O:/数据集/03_数学推理/CMATH/cmath_dev.jsonl`，按 grade 分层 `random.sample`，序列化 `问：…\n答：…`。
- 打分：`model.mean_nll(text.encode("utf-8"), device)`（`max_chunks=8` 默认）。
- 统计：`scipy.stats.spearmanr`（逐样本 + 每组均值聚合 + 三级聚合）、`scipy.stats.kruskal`（六组 + 三级）。
- 逐样本结果（grade/nll/text_len/reasoning_step/num_digits）写入系统临时目录 `%TEMP%/q2_cmath_nll_results.json`，脚本可重新生成。
- 依赖：`torch`、`scipy`（仅统计用）；无 pyarrow 依赖。
