### 0.2 与文献冲突 / 需修正的建议

- **坑①（C1 §4.2）：kd_alpha 用 `dolphin.cycle / kd_fade` 线性衰减 = 日历驱动，违反"值自成"**。
  架构设计 L11 与 life.py 成熟度 `maturity`（`life.py:327`）明确"刹车信号必须是世界信号，不是日历"（研究报告 R2 修复）。PACED 的调度也不是按时间退火，而是**按学生通过率加权** [3]。修正：衰减速率应由体检 margin 的滚动分布驱动（见 §2.1）。

- **坑②（C1 §4.3）：`apply_user_feedback` 只把 vote 映射为 reward，没有摄入"用户修正后的文本"**。
  DAgger 的核心不是"给旧样本打分"，而是**把专家在犯错状态下的纠正动作聚合进训练集** [7]。父母纠错也是"给出正确说法"而非"只给一个赞/踩"。修正：增加 `correct(eid, corrected_text)` 路径，把修正文本作为新经验喂入（见 §2.2）。这是从"奖励信号"（类比级）升级为"纠正示范"（同构级）的关键一步。

- **坑③（C1/C2 共同）：把"元数据难度"直接当"模型难度"使用，文献有明确警告**。
  "Your Pretrained Model Tells the Difficulty Itself" 明确批评手工难度度量（如文本长度）不能反映模型自身视角 [17]；"When Do Curricula Work?" 也指出显式难度排序收益主要来自动态数据集规模而非排序本身 [11]。CMATH 的 grade 是"人类对数学难度的标注"，对字节级小模型而言，一道 grade-1 应用题可能因生僻字而 NLL 很高。**必须做 grade↔NLL 对齐实验**（见 §3-问题2），用免费 surprise 信号校准档位映射。

### 0.3 文献坑（C1/C2 未提到，需要补进设计）

1. **显式课程 vs 随机排序的基准收益之争**（"When Do Curricula Work?" ICLR 2021）：
   标准基准上 curriculum 相对 random 优势**微弱**，收益主要来自"动态训练集大小"；仅在有限时间预算/噪声数据下 curriculum 显著有效 [11]。海豚的 L4 带通本身已是"动态训练集"，所以**课程排序层的边际收益必须 A/B 实验验证**，不能默认有效。
2. **课程 × 学习率衰减的耦合**（"How LR Decay Wastes Your Best Data"）：
   curriculum 在**恒定 LR**下显著优于随机，但在标准 LR 衰减下优势消失 [18]。海豚用的是 Plasticity 自适应 LR（`adapt.py`，惊讶度门控上浮），**不是单调衰减 schedule**——这是利好，但意味着课程调度器与 Plasticity 的耦合需要一起测。
3. **课程导致的分布塌缩**（C2 §七已提，文献侧补充）：
   ADAPT 论文指出离线硬过滤/重采样会牺牲数据多样性、损害泛化 [19]。若调度器只喂单档，缓冲惊讶度分布变窄 → `band()` 塌缩（C2 已识别）。缓解：档位间保留自然方差 + 少量邻档交错喂入（见 §1.2 的"做什么"清单）。
4. **PACED 的通过率信号 vs NLL 代理**：
   PACED 用学生**通过率 p** 加权 w=p(1−p)，因为"梯度信噪比随通过率呈钟形分布" [3]。NLL 惊讶度只是通过率的代理，不一定同分布。后续若做样本级加权（候选 C），需先验证 NLL 阈值与通过率的单调关系。

### 0.4 评审总结论

- C1/C2 的**接入点工程判断全部正确**（不动 `experience.py`、默认参数兼容测试、存档 `.get()`、解析器加键向后兼容），与文献的"分层职责"（上游任务选择 vs 训练内样本选择）吻合。
- 需要修正的两点：**教师退出从日历驱动改为世界信号驱动**（坑①）；**纠错通道从"打分"升级为"摄入修正文本"**（坑②）。
- 需要补进设计的一个认知：**显式课程的有效性本身是待验证假设**（坑 1），MVP 必须带 A/B 开关。

## 1. 最终推荐的课程调度器算法

### 1.1 算法名称与定位

**Band-Calibrated Tiered Curriculum（带通校准的分档课程）** —— 融合 C2 的元数据分档（零额外前向）与 ProCuRL 的 ZPD 策略 [2]，保留 L4 带通为最终选拔层（RHO-LOSS 语义 [1]）。

```
三层结构（每层职责不同，不互相替代）：
┌─ 层1：课程调度器（新 curriculum.py，上游喂食层）── ProCuRL 式任务选择 [2]
│     按能力 EMA 决定"下一批取哪个难度档"
├─ 层2：L4 带通选拔（experience.py，现状不改）── RHO-LOSS 式样本选择 [1]
│     只让"可学×值得学×未学"的经验进训练
└─ 层3：KD 双损失训练（life.py，仅 kd_alpha 退火）── 教师脚手架 [6][3]
```

### 1.2 明确清单

**要做什么（MVP）**：

1. `datasets.py` 4 个解析器 yield 追加 `"difficulty"` 键：CMATH=grade、GSM8K=步骤数（从英文 answer 的 `<<...>>` 计数）、SynLogic=0/1、LogiConBench=语句数。`serialize()` 不改（C2 §五确认兼容）。
2. 新增 `dolphin/curriculum.py`，`Curriculum` 类持有：`ability_ema`（`learn()` 返回/缓冲最后一条的 surprise，α≈0.05）、`per_source_tier_cursor`（断点续喂）、`tier_mix_ratio`（默认 0.2 邻档噪声）。
3. 调度策略（ProCuRL 工程化）：
   - `ability_ema < band_center - band_width`（模型觉得太简单）→ 升一档；
   - `ability_ema > band_center + band_width`（太难）→ 降一档；
   - 在带内 → 维持当前档，并按 `tier_mix_ratio` 混入相邻档样本（**防分布塌缩**，对应 0.3-坑3）。
   - `band_center/width` 读 `d.buffer.band()`（`experience.py:56`，只读）。
4. `feed_from(d, names, cursor, {}, curriculum=None)` 加关键字参数；`main` 加 `--curriculum`。默认 `None` 时行为逐字节不变（C1 §4.4、C2 §五）。
5. 存档：v3 payload 加可选键 `"curriculum"`，`load()` 用 `.get()` 缺省 `None`（C2 §五）。
6. **带 A/B 开关**：`--curriculum=off|tiered|random`。`random` 臂 = 同一批元数据样本但随机顺序喂入，用于验证"排序本身"的边际收益（0.3-坑1）。

**不做什么（红线）**：

1. **不改 `experience.py`**（带通公式、奖励钳位、去重是律 L4/L7 本体，测试钉死）。
2. **不做每条样本喂前预打分**（候选 B 的成本在 GTX 1060 上放大系数 1.125~2×，MVP 不需要；校准实验可选低频进行）。
3. **不设绝对惊讶度门槛**（值自成；档位切换只参考模型相对信号）。
4. **不让调度器直接调 surgery**（L11：数据供给是外环输入，调度器只改变喂什么）。
5. **不把课程状态塞进现有 `cursor` 字典**（会破坏 `t_g3_feed_cursor` 精确相等）。
6. **不新增数据源文件读取**（只作用于解析器已产出的记录，避免误触 test/dev split）。

### 1.3 三种候选算法对比（网络证据 × 成本）

| 候选 | 描述 | 优点 | 缺点 | 文献 |
|---|---|---|---|---|
| A. 离线排序课程（Bengio 经典） | 全语料按难度排序 + pacing 上界 | 简单、可控 | 静态排序随能力增长过期；标准基准收益微弱 [11] | [15][16][11] |
| **B. 带通校准分档课程（本推荐）** | 元数据分档 + 能力 EMA 相对带通切档 | 零额外前向；自适应；与 L4 同构 | 元数据难度≠模型难度，需校准实验 | [2][3][17][19] |
| C. 教师退出/PACED 样本加权 | kd_alpha 退火 + w=p(1−p) 加权 | 直接聚焦 ZPD 前沿，蒸馏增益最大 | 通过率需 rollout，字节级成本高；NLL 代理需验证 | [3][5] |

## 2. 教师退出与真实纠错通道最终接线方案

### 2.1 教师退出（scaffolding fade-out）

- **最终方案**：`kd_alpha` 由**世界信号**驱动，不用日历。
  - 在 `life.py` 的 `alpha` 赋值处（C1 定位 `life.py:1489-1493`）增加分支：
    ```python
    if m4 and ctl.state == STATE_WITHERING and ...:
        alpha = WITHER_KD_ALPHA
    elif getattr(dolphin, "kd_fade", None):
        fade = ctl.maturity          # 成熟度 m∈[0,1]：体检 margin 相对自身滚动分布的低分位 EMA（life.py:327，世界信号）
        alpha = kd_alpha * max(0.3, 1.0 - fade)
    ```
  - `dolphin.kd_fade` 默认 `None`（关闭），仅显式开启或 `feeding=True` 时生效——保住 `t_m4_life_equivalence`（C1 红线）。
  - **理由**：C1 原案的 `1.0 - cycle/kd_fade` 是日历驱动，违背"律固定、值自成"（life.py 成熟度 R2 修复的先例）。PACED 的调度同样是**学生状态驱动**而非时间驱动 [3]。
- **暂不做**：PACED 式 `w=p(1−p)` 样本加权（需要 rollout 通过率，字节级成本高），列为后续实验（§3-问题3的扩展）。

### 2.2 真实纠错通道（从"打分"升级为"纠正示范"）

- **最小版（C1 原案，保留）**：`apply_user_feedback(d, eid, vote)`，vote∈{-1,+1} → reward（如 +2.0 / −1.0），复用 `dolphin.feedback` → `experience.py:87` 钳位。支撑：偏好/奖励信号 [8][18]。
- **推荐版（增加 DAgger 式纠正摄入）**：
  ```python
  def correct(d, eid, corrected_text):
      """用户给出修正文本：原经验负奖励 + 修正文本作为新经验（DAgger 式聚合 [7]）。"""
      d.feedback(eid, -1.0)                          # 原输出贬值
      corrected = corrected_text.encode("utf-8")
      new_eid = d.learn(corrected, source="user_correction")  # 修正文本入缓冲，走正常带通选拔
      return new_eid
  ```
  - **为什么这样符合文献**：DAgger 的核心是"把专家在错误状态下的纠正动作聚合进训练集" [7]；用户反馈论文证明外部纠错是模型自检拿不到的独特信号 [20]。
  - **为什么安全**：修正文本是**人类提供**的真实数据，不是模型自生成内容——完全符合 L5"蒸馏永远锚定真实数据，禁止模型自生成内容当教材"。
  - **为什么比纯打分强**：纯打分只改变经验在选拔中的权重（类比级）；摄入修正文本让模型**学到正确字节序列**（同构级），且 `corrected` 会走 L4 带通——太怪挂起、太熟跳过，天然防"用户乱教"。
- **改动文件**：`feed.py`（新增 `correct` / `apply_user_feedback`）、`dolphin/datasets.py`（新增 `source="user_correction"` 无需注册——`learn` 的 source 只是字符串标签）、`tests/`（新增纠错通道测试）。
- **不需要改**：`experience.py`、`memory.py`、`probe.py`。

## 3. 需要先实验验证的开放问题（最多 3 个）

### 问题1：显式难度排序是否优于随机/线性喂食？

- **为什么是问题**：ICLR 2021 证明标准基准上显式课程收益微弱，收益主要来自动态训练集大小 [11]。海豚的 L4 带通已是动态训练集，排序层的边际收益未知。
- **最小实验设计**：
  - 三臂：`linear`（现 DEFAULT_ORDER 线性喂食）/ `tiered`（§1.2 课程）/ `random`（同批样本随机顺序）。
  - 控制变量：同一模型种子、同一睡眠参数、**相同总字节预算**、同一探测集。
  - 数据：CMATH + GSM8K + SynLogic 三源（C2 推荐的难度信号最全的三源）。
  - 指标：体检 margin 轨迹、probe NLL 终值、`band()` 宽度变化（监测分布塌缩）。
  - 判定：`tiered` 的 probe NLL 显著优于 `random`（如 ΔNLL>0.02）才继续投入；否则课程调度器降级为"仅做元数据分档存档"，不作为默认喂食路径。

### 问题2：元数据难度（grade）与模型 NLL 难度是否对齐？

- **为什么是问题**：自适课程论文批评手工难度不反映模型视角 [17]。CMATH grade 是"人类数学难度"，对字节级模型可能是另一回事（生僻字/格式噪声主导惊讶度）。
- **最小实验设计**：
  - 零成本测量：用现有 `learn()` 日志，线性喂入 CMATH 全部 6 个 grade，记录每条样本的 `surprise`。
  - 统计：计算 `grade` 与样本平均 surprise 的 Spearman 相关；分 grade 看 surprise 分布是否单调。
  - 判定：若相关系数 ≥0.5 且 grade 间分布分离 → 元数据难度可用（MVP 成立）；若 <0.3 → 难度轴改为**用 surprise 分位数动态分档**（模型自定义档位），元数据仅作辅助标签。

### 问题3：kd_alpha 退火（教师退出）是否提升体检通过率？

- **为什么是问题**：PACED 的增益来自"聚焦学生 ZPD 前沿"的蒸馏 [3]，但那是通过率加权；时间/成熟度驱动的退火是否有同等增益、会不会退火过快导致学生失去锚定，文献无直接答案。
- **最小实验设计**：
  - 两臂：`constant`（kd_alpha=0.5，现状）/ `fade`（§2.1 世界信号驱动退火，`dolphin.kd_fade` 开启）。
  - 控制：同种子、同数据顺序、同睡眠步数。
  - 指标：每周期体检 margin 轨迹、换班成功率、probe NLL 终值。
  - 判定：连续 N=30 周期上 `fade` 臂的累计换班成功次数或 probe NLL 优于 `constant`，才把 `kd_fade` 从"默认关"改为"默认开"（仍保留总开关）。
