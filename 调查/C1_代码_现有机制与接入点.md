## 1. 结论先行（可落地）

**两个特性都可落地，且最小改动集很小——核心接口（带通选拔、奖励钳位、蒸馏锚定、喂食游标）已经为它们预留好了位置。**

| 特性 | 可落地性 | 最小改动集 | 成本 |
|---|---|---|---|
| 课程调度器（按能力动态调难度/顺序） | **可落地**，推荐做成"喂食上游调度器"，**不动 experience.py** | 新增 `curriculum.py`；`datasets.py` 各解析器追加 `difficulty` 键（向后兼容）；`feed.py:feed_from` 增加一个带默认值的 `curriculum=None` 关键字参数 | 中 |
| 真实纠错通道（点赞/点踩） | **可落地**，`feedback(eid,reward)` 链路已通，只差"用户事件 → reward 映射 + 入口" | 新增一个反馈入口函数（约 10 行，放 `feed.py` 或 `dolphin.py`），复用 `dolphin.feedback`（`dolphin.py:191`）与 `experience.select` 的钳位（`experience.py:87`） | 小 |
| 教师逐步退出（KD fade-out） | **可落地**，3~5 行改动 | 在 `life.py:1489-1493` 的 `alpha` 计算处加周期衰减（默认关/仅 feeding 路径，保 M4-E 等价性测试） | 小 |

**关键发现**：
- `experience.py` 的 `select()` 已经支持负奖励真实压分（`experience.py:87-88`），v3 存档已持久化 `reward`（`dolphin.py:284`）——真实纠错通道的"存储/选拔消费"两端都已就绪，缺的只是"入口"。
- 课程调度器**不应**改 `experience.py` 的带通公式（那是律 L4 本体，测试 `t_l4_band`/`t_l7_decay`/`t_l9_negative_reward` 钉死）。更稳的做法是在 `feed_from` 的上游决定"下一条喂什么"，让带通继续只做"惊讶度门控"。
- `feed_from` 的签名（`feed.py:269-271`）已经是一长串带默认值的参数；再加一个 `curriculum=None` 关键字参数不会破坏 `t_g3_feed_cursor`/`t_g3_structural_reward`（它们以位置参数调用 `feed_from(d, names, cursor, {})`）。

## 4. 接入点详情

### 4.1 带通选拔（L4）现状与"课程难度"叠加

**现状**：
- `ExperienceBuffer.band()`（`experience.py:56-72`）：带通中心 = 惊讶度中位数，宽度 = IQR；样本 <64 时向先验带收缩。`PRIOR_CENTER = ln(256) ≈ 5.545`（`experience.py:53`）是"随机初始化模型对任意字节流的理论惊讶度"，用于冷启动门控；`PRIOR_WIDTH = 2.0`。n≥64 后纯经验带。
- `select()`（`experience.py:74-100`）：`score = band_w × (1+rw) / (1+prior)`，按分排序，预算字节耗尽即停。

**叠加"课程难度"信号的建议**：
- **推荐方案（不动律）**：课程调度器放在 `feed_from` 上游（`feed.py:293` 的 `iter_source` 迭代处），按"模型当前能力"（读 `d.buffer.band()` 中心或 `d.probe_loss(d.awake())`）动态选择下一条记录的难度。`experience.py` 一行不改，`t_l4_band` 等测试零风险。
- **备选方案（改 select 签名）**：若确需在选拔层叠加难度，可给 `Experience` 增加 `difficulty` 字段（`__slots__` 在 `experience.py:13`，需同步改 `add`/`select`/`save`/`load`），并把 `score` 改为 `band_w × (1+rw) × diff_w / (1+prior)`。**成本高、破坏面大**（`dolphin.py:284` v3 存档四元组、`t_g7_eid_stability`、`t_l4_band`、`t_l7_decay`、`t_l9_negative_reward` 全部受影响），不推荐。

### 4.2 KD 蒸馏（L5）现状与教师退出

**现状**（`life.py:1484-1520`，`sleep.py:94-117` 为冻结的历史件）：
- 硬标签 = 真实字节 `y`（`life.py:1506`）；软标签 = 醒脑对**同一批真实字节** `x` 的输出 `t_logits`（`life.py:1507-1508`）；`p_t = softmax(t_logits/kd_T)`（`life.py:1511`）；`loss = (1-α)·CE + α·KD`（`life.py:1514`）。
- `kd_alpha` 默认 0.5、`kd_T` 默认 2.0，是 `run_cycle` 的参数（`life.py:1389`）；`maybe_sleep`/`feed` 调用时未覆盖（`dolphin.py:227-228`、`feed.py:180`）。

**教师逐步退出（fade-out）的改法**：
- 位置：`life.py:1489-1493`（`alpha = kd_alpha` 的赋值处）——这里已经是"手术验收周期用 `WITHER_KD_ALPHA`"的特判点，再加一个"周期衰减"分支最自然。例如：
  ```python
  if m4 and ctl.state == STATE_WITHERING and ...:
      alpha = WITHER_KD_ALPHA
  elif getattr(dolphin, "kd_fade", None):
      alpha = kd_alpha * max(0.1, 1.0 - dolphin.cycle / dolphin.kd_fade)
  ```
- **红线**：`kd_fade` 必须是 Dolphin 上新属性且默认 `None`（关闭），或仅 `feeding=True` 时生效；否则 `t_m4_life_equivalence`（`test_conformance.py:1538`）会比较 `life.run_cycle` 与 `sleep.run_cycle` 两周期行为，周期衰减会让两者不一致。
- `kd_T` 也可做类似退火（温度上升 = 软标签更硬），但改 `alpha` 更直接。

### 4.3 反馈/纠错通道

**现状接线**：
- `dolphin.feedback(eid, reward)`（`dolphin.py:191-192`）→ `buffer.feedback`（`experience.py:42-47`）直接写 `e.reward`。
- `feed.py` 的自动奖励：`structural_reward`（`feed.py:213-229`）对同文重复给 `-n` 负奖励，经 `d.feedback` 写入。**注意：这只是结构信号（重复计数），不是内容评价**（`feed.py:218-220` 明说"真正的内容奖励留给部署时代"）。
- `_threshold_feedback`（`life.py:284-298`）是**睡眠频率阈值反馈**，不是经验奖励——别混淆。
- 奖励钳位 `[-0.9, 9.0]` 唯一定义在 `experience.py:87`（`rw = max(-0.9, min(e.reward, 9.0))`），**在选拔时钳位**；`e.reward` 本身以原始值随 v3 存档持久化（`dolphin.py:284`）。
- `serve()` 返回 `(resp, eid)`（`dolphin.py:187`）——交互式部署已经能把"哪条回复"交给用户。

**真实用户纠错的最小改动**：
1. 新增一个入口函数（放 `feed.py` 或 `dolphin.py`，约 10 行）：
   ```python
   def apply_user_feedback(d, eid, vote):  # vote ∈ {-1, +1}
       reward = 2.0 if vote > 0 else -1.0   # 映射可调，钳位由 experience.py:87 兜底
       with d.feed_lock:
           ok = d.feedback(eid, reward)
       if ok:
           d.save(FED_STATE)  # 立即持久化（可选）
       return ok
   ```
2. 无需改 `experience.py`（钳位已存在）、无需改 `dolphin.save/load`（reward 已随档）。
3. 若要"点踩后该经验尽快被消化/排除"，可顺带在 `apply_user_feedback` 里 `trainer.request_sleep()` 触发一个周期——非必需。

### 4.4 喂食驱动器与课程调度器

**现状**：
- 状态机：`main`（`feed.py:407`）→ `feed_from` 正式喂食（`feed.py:269`）→ 数据尽 → `guard_loop` 反刍（`feed.py:324`）→ `ruminate`（`feed.py:232`）从记忆库做梦注入；部署侧新经验流入（`learn_total` 口径）自动恢复正式喂食（`feed.py:342-347`）；连续 `max_idle` 个空选拔周期收工（`feed.py:348-350`）。
- 参数：`--sources`（逗号分隔源）、`--limit`（最多喂入条数）、`--sleep-every`（每 N 条通知睡眠）、`--sleep-steps`、`--model`、`--resume`（按游标续喂）、`--no-guard`、`--max-idle`、`--feed-interval`、`--serve-every`（`feed.py:364-387`）。
- 线程同步：主线程 `learn()` 只做 `buffer.add`（锁内毫秒级，`dolphin.py:208-212`）；`SleepTrainer.run` 用 `wake.wait(0.2)` 轮询触发（`feed.py:165`），压力/溢出也可自主触发（`feed.py:169-171`）；动睡脑前等 `learn_busy` 清零（`life.py:1468`）；换班在锁内翻 `awake_idx`（`life.py:1547-1548`）；退出时 `join` 收尾（`feed.py:488-489`）。
- 游标：`cursor = {"sources","source_idx","record_idx"}`（`feed.py:428`），`--resume` 从游标续喂（`feed.py:429-441`），随档透传（`dolphin.py:302/371-372`）。

**新增"课程调度器"需要改的函数签名**：
- `feed_from`（`feed.py:269`）增加 `curriculum=None` 关键字参数。当前迭代是 `itertools.islice(iter_source(name), start, None)`（`feed.py:293`）；有调度器时改为 `curriculum.iter(d, name, start, cursor)` 返回的迭代器。
- `main`（`feed.py:407`）增加 `--curriculum` 参数，构造调度器实例传入 `feed_from`。
- 调度器需要模型能力信号：读 `d.buffer.band()`（`experience.py:56`）或 `d.probe_loss(d.awake())`（`dolphin.py:116`）——两者都是只读，不破坏现有律。
- `datasets.py` 各解析器在 yield 字典里**追加** `difficulty` 键（`serialize` 只读 `prompt/answer`，`datasets.py:252-255`，追加键完全向后兼容）。

## 6. 与背景文件/规格描述不符之处（代码内实锤）

1. **`adapt.py` 是"高通"不是"带通"**：`Plasticity.next_lr` 的公式 `ratio = |surprise-center|/width` 单调上升，惊讶度越高学习率越大（撞 `lr_max`），与律 L4"太怪挂起"字面矛盾。代码自身已标注（`adapt.py:34-41`），`架构设计.md §7` 与 `交接文档.md §6.4` 均挂账待用户裁决。**这直接影响"课程调度器按带通选难度"的语义**——当前系统的"能力估计"若用 `band()` 中心是带通，但学习率控制是高通。
2. **CMATH 用 dev split 当训练粮**：`datasets.py:129` 读 `cmath_dev.jsonl`，违反 `datasets.py:4-5` 自己声明的"test/dev 等评测 split 永不进训练粮（律 L8 前置）"。`交接文档.md §6.5` 已挂账。
3. **测试数量文档口径与静态计数不一致**：`交接文档.md` 称"符合度 238/238 + 成长配套 59/59"，而静态 `grep` 到 `check("` 调用点分别为 221/41（运行时因循环展开而更多）。这不是代码缺陷，但**报告测试数时应以运行输出为准**，不要引用静态计数。
4. **`dolphin/sleep.py` 仍是"活"文件但已冻结**：`sleep.py` 的 `run_cycle` 仍被 `t_m4_life_equivalence` 调用做等价性对比（`test_conformance.py:1543`），`varied_replay` 仍被 `life.py:178` 复用——改动时**不要**删 `sleep.py`，也不要改它的行为。
