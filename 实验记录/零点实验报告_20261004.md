## 三、实验过程

- **阶段一（清零后首跑）**：`feed.py --sources logiqa,cmath,gsm8k --limit 3000 --sleep-every 300 --sleep-steps 120 --serve-every 50`。喂入 3000 条（logiqa，碎片跳过 0），周期 0–9，优雅退出（退出原因 limit）。
- **阶段二（反刍观察相）**：`feed.py --resume --sources cmath --sleep-every 300 --sleep-steps 120 --serve-every 50`（无 limit）。原因：**发现 feed.py 的控制流是"到 limit 即收工"，守护/反刍只在"数据源耗尽且无 limit"时进入**（指令中"limit 到守护模式自然接管"与代码不符，已在日志+报告如实记录）。阶段二续喂 cmath 589 条（碎片跳过 11）→ 数据尽 → 守护模式接管 → 反刍 1600+ 条 → 观察 3 个反刍周期后经停止旗标发 CTRL_BREAK 优雅退出（第一次信号即生效，rc=0，梯度更新未被腰斩：cycle 13 完整收尾后才存档）。

## 五、异常与处理（全部如实）

1. **抓到并修复一个真实生产 bug（本实验最大收获之一）**：阶段一周期 8、9 两次 `周期异常终止（部署不停机）：RuntimeError("Expected a 'cuda' device type for generator but found 'cpu'")`（行 227、237）。定位 `dolphin/life.py` `_redo()`：`torch.Generator()` 默认 CPU，而权重在 CUDA——**ReDo 钩子在 GPU 上首次真实触发（有休眠单元可回收）即崩**。常备测试全在 CPU 上跑，从未踩到；两个周期的损失=训练白做后回滚，且异常兜底（回滚+计数+部署不停机）本身按设计工作。修复：`torch.Generator(device=d.device)` 一行（life.py:336 附近，注明来源）；修复后双套件复验 **185/185 + 59/59 全绿**（交接文档写 174 项，差值为文档落笔后的增补，与本次改动无关），周期 10–13 的 ReDo 真实回收即修复生效的证明。
2. **挂账（未修，超出本实验范围）**：`dolphin/surgery.py` 存在同类"CPU generator 对 CUDA 权重"模式（如 `break_symmetry_dmodel`，行 405）——只在结构手术真实执行时触发（本实验不可达；且 pre_train 异常同样被部署兜底接住）。surgery.py 距离"函数保持"对质红线很近，建议单独立项核查修复，勿顺手改。
3. **feed.py --limit 与守护模式的关系**：实测到 limit 即收工、不进反刍（阶段一 `退出原因：limit`，反刍 0 条）。已按 §三 的两阶段设计补齐反刍观察。是否要改"limit 后也进守护"由用户裁决（涉及防真死转语义）。
4. **预检时测试套件崩溃一处（非本次改动引起）**：`verify_cold_quarantine` 的明细格式化未处理"生产冷层文件合法缺席"（`_fingerprint` 返回 None → `after[1][:12]` TypeError）。关键事实：崩溃发生在 `before==after` 分支=**防线语义本身通过**（无测试污染生产路径），崩的只是打印。清零态下的既有测试边界缺陷，挂账不改（红线：既有测试不许改）；新冷层文件出现后该检查自然恢复（收工复跑 185/185 即证）。
5. **查房总结"反刍 0 条"是记账伪影**：中断打断了 guard_loop 的返回路径，`ruminate_total` 未累计；真实反刍量以 `[反刍]` 日志行为准（1600+ 条）。已知小账，不改代码。
6. **跳过 burn_in.py 的决定**：交接 §2 记录"用户超频 +360/+220 已过 burn_in 体检"（硬件未变），用户指令亦未要求，为省时跳过；全程 35 分钟 GPU 长跑无显卡异常（训练轨迹、体检数值连续稳定为旁证）。
7. **优雅退出机制**：自建启动器（独立进程组 + 停止旗标 → CTRL_BREAK，feed.py 的 `_sigbreak_to_interrupt` 承接）。两次阶段均第一次信号即优雅退出，rc=0，无需 terminate 兜底。

## 六、诚实边界（什么证明了、什么没证明）

**证明了的**：V1 自循环（喂入→睡眠→门控→换班→记忆→反刍→跨重启续喂，8/8 门控全过、8 次换班、零静默回滚）；V2 边训练边回答（65/71 演示在训练窗口内完成，28.55s 延迟=并发铁证，部署线程零阻塞）；V3 钩子在位（账本测量→ReDo 真实回收→锚持续落锚，全部有日志痕迹）；从零学习真实发生（probe 5.6854→5.3563，−0.329 NLL / −5.8%，门控 margin 全程为正且远超 ε）。

**没证明的（需要更长的实验，如实说明）**：

- **a) 结构手术（wither/grow）未触发——设计内的正常现象**。手术排程需要体检平台期（连续 3 周期改善<ε 起步，手术还要 ≥3 档）。从零学习期损失还在快速下降（每周期 margin≈0.03，是 ε 的 30 多倍），plateau 恒为 0——正如生物在稳定环境不长新器官，生长发生在平台期。观察手术首触发需要喂养至平台期（交接 §6-2 预计"3 周期起步，别催"，实际可能需要数万条量级）。
- **b) 行为质量未证明**：57M 从随机起步、喂 3589 条，回答仍是抽象字节序列（查房演示与 71 次服务演示如实原样记录）。本次实验证明的是学习机器的**机构**在转（惊讶度下降、门控通过、记忆闭环），不是"会做题"。
- **c) 幽灵探针的"增益判据"未经过真实触发检验**（GHOST_GAIN_MIN=1e-4 仍是律定初值，未进入在线自校准回路）。
- **d) 长期可靠性未证明**：冷层复活（hits 达标→升热层）本短跑未见真实发生；一天级长跑（数万条、多次 --resume、断电自续）仍待做。
