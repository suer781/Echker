### 修复：并列 NLL 导致睡眠周期空转崩溃（G3-a 红）
- 现象：`tests/test_conformance.py` 交接时声称 78/78，实际 **77/78**，G3-a 失败（`注入 1098 条 周期 0 次`）。
- 根因（已最小复现）：`feed.py:188` 与 `dolphin/sleep.py:132` 的
  `sorted((mean_nll(...), e) for _, e in sel)` —— NLL 并列时元组比较去比 `Experience`，
  而 `Experience` 无 `__lt__` → `TypeError: '<' not supported between instances of 'Experience'`。
- 为什么生产必崩：守护模式反刍反复做梦**同几条旧经验** → 同字节 → 同 NLL → 必然并列。
  崩溃点在 `d.swap()` **之后**，故每崩一次白扔一个已训完的睡眠周期（cycles 不计数、d.cycle 不推进、
  预算与 LR 反馈整段跳过），只留一句"周期异常终止（部署不停机）"——即"看起来在跑、实际空转"。
- 修法（子 Agent 执行，已复核）：两处均改`key=lambda t: (t[0], t[1].id)`，
  次级键用稳定整数 id 保证并列顺序可复现；**不给 Experience 加 `__lt__`**（会引入"经验可比"的错误语义）。
- 复核证据：test_conformance 连跑 3 次均 78/78；12 条同内容经验（唯一 NLL 种类=1）走 trainer_cycle
  全路径 passed/swapped 正常、note 入库 5 条、并列段按 id 升序；G3-a 35.9s → 7.86s（不再空转）。
